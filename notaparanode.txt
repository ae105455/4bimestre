2. SI NODE O NPM NO SON RECONOCIDOS
--------------------------------------------------------

Comprueba si Node.js esta instalado en la ubicacion habitual:

Test-Path "C:\Program Files\nodejs\node.exe"

Si devuelve True, comprueba los ejecutables directamente:

& "C:\Program Files\nodejs\node.exe" -v
& "C:\Program Files\nodejs\npm.cmd" -v

Si funcionan directamente pero no con node o npm, cierra y
vuelve a abrir PowerShell. Si aun no funcionan, revisa que
C:\Program Files\nodejs este en el PATH de Windows.

Agregarlo con:

$env:Path += ";C:\Program Files\nodejs"

solo modifica el PATH de la ventana actual de PowerShell.
Para conservar el cambio, configura el PATH de usuario en
Windows y vuelve a abrir la terminal.

Si Node.js no esta instalado, se puede instalar la version
LTS desde una terminal con winget:

winget install --id OpenJS.NodeJS.LTS --exact

Despues, abre una terminal nueva y vuelve a comprobar node -v
y npm -v.

Si PowerShell bloquea el script npm.ps1, prueba npm.cmd en
lugar de cambiar la politica de ejecucion:

npm.cmd -v

No es necesario ejecutar Set-ExecutionPolicy para configurar
Node.js o TypeScript en este proyecto.


3. TYPESCRIPT
--------------------------------------------------------

TypeScript ya se instalo globalmente en esta computadora con:

npm install -g typescript

Comprueba la version con:

tsc -v

En esta computadora se obtuvo:

Version 7.0.2

Las versiones pueden ser distintas. Una instalacion global
sirve en esta computadora, pero no registra la dependencia
en el proyecto. Para que el proyecto use una version
registrada y reproducible, se puede instalar localmente:

npm install --save-dev typescript

Luego se puede ejecutar esa version con npx:

npx tsc -v

Si el comando tsc no se reconoce despues de una instalacion
global, npm config get prefix muestra la carpeta de npm.
En Windows, los comandos globales suelen estar en la carpeta
que muestra npm config get prefix. Agregarla con $env:Path
solo afecta la ventana actual; para conservarlo, configura el
PATH de usuario en Windows y vuelve a abrir la terminal.


4. CONFIGURACION DEL PROYECTO
--------------------------------------------------------

Este proyecto ya tiene un archivo tsconfig.json.

No ejecutes tsc --init si el archivo ya existe. Ese comando
crea una configuracion nueva y puede mostrar un error si ya
hay una.

Para compilar el proyecto usando su configuracion, ejecuta:

npx tsc -p .

Si TypeScript esta instalado globalmente, tambien puedes usar:

tsc -p .

La compilacion del proyecto puede incluir todos los archivos
TypeScript indicados por tsconfig.json; no necesariamente
compila solo scriptdd.ts.

En la configuracion actual estan activados sourceMap,
declaration y declarationMap. Por eso se generan archivos
.js, .js.map, .d.ts y .d.ts.map para los archivos compilados.
Como no se configura outDir, los archivos generados quedan
junto a los archivos TypeScript.


5. CREAR Y EJECUTAR UN ARCHIVO TYPESCRIPT
--------------------------------------------------------

Un archivo es contenido del proyecto, no un comando de
PowerShell. Por ejemplo, scriptdd.ts puede contener:

let nombre: string = "Juan";

console.log("Hola " + nombre);

Comprueba que el archivo existe con:

dir scriptdd.ts

Compila el proyecto desde la carpeta que contiene
tsconfig.json:

npx tsc -p .

Si la compilacion termina sin errores, ejecuta el JavaScript:

node scriptdd.js

Resultado esperado para el ejemplo:

Hola Juan

Flujo:

scriptdd.ts
    -> compilador de TypeScript
    -> scriptdd.js
    -> Node.js
    -> resultado en la terminal

Los nombres tsconfig.json, scriptdd.ts y scriptdd.js no se
ejecutan escribiendolos solos en PowerShell. Usa comandos
como dir para ver archivos, tsc para compilar y node para
ejecutar JavaScript.


========================================================
GIT Y GITHUB
========================================================

Guardar con Ctrl + S guarda el archivo en la computadora,
pero no crea un commit ni envia cambios a GitHub.

Flujo:

1. Guardar el archivo en VS Code.
2. Crear un commit local con Git.
3. Enviar el commit a GitHub con git push.


6. REVISAR LOS CAMBIOS
--------------------------------------------------------

git status

Muestra los cambios locales y si hay archivos preparados
para commit.


7. PREPARAR Y REVISAR EL COMMIT
--------------------------------------------------------

Es preferible agregar solo los archivos que quieres guardar:

git add notaparanode.txt

Puedes agregar otros archivos indicando sus nombres. Si usas
git add ., revisa cuidadosamente que no estes incluyendo
archivos generados u otros cambios no deseados.

Comprueba que archivos se prepararon:

git status
git diff --cached


8. CREAR EL COMMIT
--------------------------------------------------------

git commit -m "Actualizacion de TypeScript"

El commit guarda una version en el historial local de Git.
Si Git informa que no hay cambios preparados, revisa git
status y agrega los archivos que corresponda.


9. ENVIAR A GITHUB
--------------------------------------------------------

git push

Esto envia los commits locales a la rama remota configurada.
Si Git informa que no hay una rama upstream configurada,
consulta las instrucciones del repositorio antes de elegir
que rama publicar.

Despues comprueba el estado:

git status -sb

Si la rama local y la remota aparecen sincronizadas, no hay
commits locales pendientes de enviar. Para confirmar que los
cambios aparecen en GitHub, tambien puedes revisar el
repositorio en el navegador.

El mensaje "nothing to commit, working tree clean" significa
que no hay cambios locales sin guardar en Git. Por si solo,
no confirma que GitHub haya recibido los commits; para eso,
comprueba git push y que la rama local este sincronizada con
la rama remota.
